Two cooperating sub-packages form a thin state layer over the pure `src/engine`:

- `src/state/store.ts` creates a single `useGameStore` via `zustand/create` wrapped with `persist` + `createJSONStorage(AsyncStorage)`. The store exposes a `GameStore` interface whose actions (`setWindow`, `assignHeroForWindow`, `checkIn`, `evaluateCurrentNight`, `canResurrect`, `applyResurrection`, `startNewHero`, `openChest`, `equip`, `changeWindow`, `useHourglass`, `toggleDemoMode`, `reset`) are thin wrappers around functions from `actions.ts`.
- `src/state/actions.ts` contains pure-ish action helpers (`tryResurrect`, `tryChangeWindow`, `runNightTurn`, `tryUseHourglass`, `openGrantedChest`) that call into `src/engine/*` modules and push typed `GameEvent`s onto a bounded (last 100) event log.
- `src/contracts/` holds the frozen M0 contracts: `types.ts` defines `GameState`, `Hero`, `SleepWindow`, `NightRecord`, `ArtifactId`, etc.; `events.ts` defines the `GameEventType` union and `GameEvent` shape; `flags.ts` is a `as const` feature-flag object; `mock.ts` implements a spec-shaped in-memory scoring engine so UI screens can be built without the real engine.
  Dependency direction is one-way: `state` → `engine` + `contracts`; `contracts` has no dependencies on either. Persistence partializes only the fields listed in `partialize`, keeping `hydrated` and transient flags out of storage.
