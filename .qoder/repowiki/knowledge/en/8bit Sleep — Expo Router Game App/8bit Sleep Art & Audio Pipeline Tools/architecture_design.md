The module is organized into three cooperating layers:

- `art/` — procedural pixel-art generators built on a small Canvas API (`canvas.py`, `drawutil.py`) and a shared palette (`colors.py`). Each scene or asset type lives in its own module (e.g. `scenes.py`, `heroes.py`, `hero_defs.py`, `hero_parts.py`, `hero_profile.py`, `hero_weapons.py`, `contact.py`, `cosmetics.py`, `hearts.py`, `props.py`, `tether.py`, `logo.py`) and composes primitives from `scene_common.py` to produce 256×144 or 64×64 frame strips written to `assets/_src/<category>/`.
- Top-level scripts are CLI entry points that drive the pipeline: `pixelate.py` is the deterministic art post-processor (downscale → palette quantize via `palette.json` → optional outline → x4 nearest-neighbor upscale), `generate_audio.py` synthesizes NES-style WAV files using pure stdlib oscillators/LFSR/noise, and `pixellab_gen.py` / `pixellab_batch.py` / `pixellab_atmo.py` / `pixellab_walkfix.py` / `pixellab_adopt.py` wrap the external PixelLab REST API (`api.pixellab.ai/v1`) for AI-assisted generation.
- `manifest_lib.py` is the single source of truth: it reads/writes `assets/manifest.data.json` and regenerates `assets/manifest.ts` with typed exports (`SPRITES`, `SCENES`, `AUDIO`, etc.) that the UI imports. Every pipeline script calls `manifest_lib.update()` after writing an asset so the TS manifest stays consistent.

Dependency direction is one-way: `art/*` modules depend only on `canvas.py`/`colors.py`/`scene_common.py`; top-level scripts import `manifest_lib` and optionally `art.*`; nothing in `art/` depends on the PixelLab tools.
